本版本引入按终端划分的 Profile 与共享守护进程，让多个 Agent 在同一账户下协作。版本记录日期为新加坡时间 2026 年 10 月 25 日；实际发布与远端部署状态分别以 GitHub Release 和部署记录为准。

- **薄客户端与守护进程。** CLI 自动连接或启动本机 daemon；配置、SQLite 数据库与安装目录统一放在 `~/.amail`，Windows 对应 `%USERPROFILE%\.amail`，二进制放在 `bin` 子目录。`config.toml` 仅覆盖需要改变的默认值，由 daemon 统筹网络、邮件处理与并发资源。
- **按终端隔离 Profile。** 同一终端的多个 CLI 进程共享当前 Profile；一个 Profile 同时只能由一个终端激活。停用保留占用、可再次找回；释放才交还占用，连续 30 分钟没有实际使用也会自动释放。`user` 及由它创建的 Profile 会保留，其余 Profile 在释放时删除，名称可以重新分配。
- **人类逐次授权。** `user` 默认每次受保护操作都需要在浏览器确认；YOLO 是人类显式关闭此保护，不是 Agent 可以自行开启的权限，也不代表付费或预算授权。Profile 不是操作系统安全沙箱。
- **不可抢占的读写占用。** 同一邮箱允许多个 Profile 共享读，或一个 Profile 独占写。云端验证会话与占用，过期会话、重启 daemon 或另开 CLI 都不能夺取其他 Profile 的占用。
- **临时测试邮箱。** 任何活动 Profile 可用 `amail address add NAME --tmp` 注册 `tmpaddr.moesegfault.dev` 地址，最长六小时。释放不通知、不可恢复，到期立即不再返回查询结果；旧数据清理、路由退役和固定一小时冷却完成后才可复用，同名新持有者不能取得前一代的数据。晚到来信风险由使用者处理，不适合长期身份或密码找回。
- **释放前导出。** `amail mailbox export NAME@tmpaddr.moesegfault.dev --output history.zip` 在邮箱仍有效且可读时下载完整分页中的邮件 ZIP、摘要和邮箱清单。导出不会延长寿命；过程中到期或代际改变会失败，不会把部分备份当作成功。
- **同一账户共享资源。** 普通邮箱的 Free / Lite / Plus 包含数量为 1 / 3 / 5，临时邮箱为 3 / 6 / 10；两类地址仍共享账户发信与储存资源池。普通 `mail.moesegfault.dev` 地址只允许 `user` 注册，既有地址、付费权益和明确批准的预算继续保留。

## 升级与兼容

升级前先停止旧 CLI 进程，并执行 `amail daemon stop`，再替换二进制。CLI 与配套 Agent Skill 使用同一 Release，核对 `SHA256SUMS`；下一次操作会自动启动对应 daemon。启用 Profile 前请协调旧自动化：尚未启用的账户继续支持 v0.2.0 客户端；启用后必须使用有效 Profile 会话，旧客户端需要升级，停用 Profile 不会恢复无会话访问。

原有 JSONL 输出、ZIP 消息包和显式已读更新保持兼容。旧 v0.2.0 尚未提交的 `preparing` 发信意图可安全补充新邮箱字段，保留原幂等键（Idempotency Key）、内容和消息身份；已接受或状态不确定的意图不会被重置为新发送。请保留原 ZIP、键和日志，不能因为升级而换键重发。

自动第三方语义索引的隐私边界不变：即使不使用 `--semantic`，符合条件的普通及临时邮件主题和正文片段仍会发送给 OpenRouter 及其上游模型；关闭诊断遥测不关闭此处理。版本发布不替代具体环境的端到端部署验收。
