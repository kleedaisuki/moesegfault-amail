# Automatic semantic indexing: independent code review (2026-09-29)

Scope: repository state through `9d64617`, covering the scheduled Worker indexing path, provider request, search consumption, homepage/manual, CLI help, and both amail Skill copies. This is a static review, not hosted CI, a provider-retention audit, or deployment verification. The product decision is **automatic indexing with advance disclosure**, not account opt-in; see [the privacy decision](semantic-indexing-privacy-decision.md).

## Findings to resolve before release

1. **P1 — delete-before-transfer race.** `crates/mail-worker/src/lib.rs:411-416` materializes up to 20 active messages with their subject/body text before looping over sequential provider calls. If a user deletes a later selected message while an earlier provider call is in flight, that later text is still sent after deletion. The write at `:419` also lacks `deleted_at IS NULL`, allowing a vector to be stored on a soft-deleted row. This is a concrete race with the decision's statement that deletion before claim prevents a new transfer. Select opaque IDs first and recheck/claim each still-active row immediately before its own call; conditionally write only if still active and the input version still matches. A call already in flight cannot be undone, and public language should not suggest otherwise.

2. **P1 — permanently failing rows can starve the global index.** `lib.rs:411-417` always picks the 20 oldest NULL-vector rows and discards each provider error without recording an attempt, backoff, or quarantine. Twenty rows with deterministic provider failures monopolize every Cron pass across all accounts. Later mail never reaches the provider, and a semantic search encounters `semantic_index_incomplete` rather than eventually becoming usable. The durable due-work ledger, bounded retry/quarantine, and owner fairness described in the privacy decision are a coherent repair; simply raising the LIMIT does not remove the failure mode.

3. **Conditional P1 — vector-space metadata is not enforced.** The request model is a deployment variable (`crates/mail-worker/src/platform.rs:289`), but `lib.rs:419` writes a fixed model slug; `lib.rs:1408-1413` projects only vector JSON and `search_jobs.rs:532-544` validates only its JSON/shape through cosine. If the configured model or input projection changes while old vectors remain, a 256-dimensional result may be scored against incompatible old vectors without an error. Current production/staging configuration pins one slug, so this is a model-change gate rather than a demonstrated present-day wrong ranking. Persist actual model/input version and reject incompatible vectors, or run an explicit versioned backfill before changing the route.

## What is aligned

The current homepage (`site/src/pages/index.astro:12`), first-use/manual text (`site/src/pages/manual.md:11,73,172`), CLI root/login/auth-login/search help (`crates/amail/src/main.rs:21-26,31-32,51,75,127`), and both Skill copies (`skills/amail/SKILL.md:10,18,54`, `.agents/skills/amail/SKILL.md` corresponding lines) disclose that email-derived text is sent for automatic indexing independently of `--semantic`, while query text is additionally sent for semantic search and telemetry opt-out does not stop indexing. I found no contradictory public statement in those reviewed surfaces. The provider request sets ZDR/no-collection and disables OpenRouter response caching (`platform.rs:287-291`); these controls limit provider behavior but do not mean that no third-party transfer occurs. The UTF-8 prefix function (`lib.rs:393-400`) now enforces the 12,000-byte boundary rather than falling back to full long input.

These are source-level findings. Hosted provider-route behavior, rendered-site prominence, and deployed versions remain separate release evidence gates.
