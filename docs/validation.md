### First live native login attempt

The operator used a CI-built Windows `amail.exe` (`24082964` checkpoint) with an isolated repository-local `.temp` home. The production Identity browser flow reached the CLI callback and displayed `Login complete`, then the CLI exited with: `Attribute 'password encoded as UTF-16' is longer than platform limit of 2560 chars`. This is a **credential-storage implementation defect**, not an Identity authorization rejection: the token bundle cannot fit Windows Credential Manager's password attribute, and the callback page reported success before durable storage completed. No token or account identifier is retained in this ledger. A correct follow-up must use a short OS-protected key with encrypted local token storage, report callback success only after persistence, then demonstrate `amail auth status` and an authenticated mail API request on the same isolated home. Do not repeat Identity account setup once its authorization succeeded; retest the failed persistence/use path.
