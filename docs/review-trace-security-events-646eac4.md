# Review: one-shot trace Security Events probe (`646eac4`)

## Verdict and scope

**GO for a single, explicitly confirmed, read-only hosted diagnostic.** No substantive defect was found in the reviewed source and synthetic fixtures. This review does not establish that the existing Cloudflare token has Analytics Read, that the live GraphQL schema accepts the hostname filter, or that sampled events can attribute the historical request. The live result must remain a diagnostic classification, not a retained-log privacy acceptance.

Reviewed `infra/provider/probe_staging_trace_security_events.py`, its tests, the manual job in `.github/workflows/ci.yml`, the incident and design notes, and Cloudflare's official GraphQL/Security Events documentation. No live provider request or local test was run in this review.

## Contract checks

| Concern | Finding |
| --- | --- |
| Exact incident and scope | `RUN_ID`, confirmation, staging host, and inclusive 2026-09-30 04:58:42–05:00:42 UTC are constants. The GraphQL request uses `zones(filter: {zoneTag: ...})`, a host filter and both time bounds; the response must contain exactly one zone and every row must match host and time. |
| Boundedness | One POST, 20-second timeout, no redirect or retry, 65,536-byte response cap. A 100-row result fails as potentially truncated; only 0–99 rows can be classified. No fallback widens the query. |
| Output privacy | The selected fields exclude IP, URL, path, query, Ray ID and user agent. Provider response bodies, errors, redirect targets and free-form descriptions are never printed. Actions and sources map to closed labels; descriptions are exact-match classified in memory. All exception paths emit fixed failure reasons. |
| CI authorization | The job is `workflow_dispatch`-only, branch-restricted, `environment: staging`, `contents: read`, and requires the exact confirmation in the script before network access. The existing zone/deploy token is injected only into the final step; no artifact upload exists. |
| Evidence interpretation | A sampled mitigation on this host and time is only a *candidate*. Zero or non-mitigating sampled events do not exonerate the edge. A GraphQL 401/403 reports query permission, not the mail API's failure producer. |
| Synthetic fixtures | Cover query selection, candidate semantics, empty/non-mitigating cases, unknown provider text, malformed/out-of-scope/full pages, duplicate keys, pre-network confirmation, and suppression of raw exceptions. Hosted test execution remains the CI gate. |

## Residual limits, not blockers

Cloudflare confirms `firewallEventsAdaptive`, the zone-scoped response shape, selected host field, `description`, adaptive sampling, and plan-dependent retention in its official documentation. The exact live `clientRequestHTTPHost` **filter** support is not independently proven by public examples, nor is the token's Analytics Read grant. The implementation deliberately returns `graphql_unverified` or `permission` without a wider fallback, which is the right failure mode for this time-sensitive diagnostic. A no-event result cannot establish whether the historical 403 was or was not generated by Cloudflare security.
