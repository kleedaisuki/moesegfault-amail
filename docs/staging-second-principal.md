# Second staging Identity principal for ownership isolation

Status: **source preparation only**. No second route, contact, account, verification email, or CLI session has been created by this work. The first staging principal and its `amail-e2e@moesegfault.dev` contact remain untouched. Execute this runbook only after the parent E2E owner confirms the staging deployment and routing state.

## Purpose and model

The address-isolation acceptance needs two distinct Identity `(issuer, sub)` principals with separate encrypted CLI homes. Reusing one account with two mail aliases would not prove authorization isolation. The second synthetic principal has a distinct exact **Identity contact** at the zone apex, `amail-e2e-isolation@moesegfault.dev`, not a user mailbox at `mail-staging.moesegfault.dev`. This is a test control-plane address, not a public role or permanent user address. Normal first-party registration, email verification and native OIDC/PKCE are mandatory; no D1 fixture or bearer-token injection is permitted.

The private staging verification Worker has a small explicit `TEST_RECIPIENTS` allowlist in its Wrangler configuration. Source code does not branch on “principal B”: the exact recipient is a parameter to the route and browser-registration helpers. The first alias remains the default for backward compatibility; the first account's older DPAPI credential blob remains readable, with a missing encrypted `address` interpreted only as that legacy alias. The second alias requires an explicit `--address` and a fresh run directory. The Worker accepts only configured recipients, while **each registration window still requires one independently audited literal Email Routing rule**. Route ownership checks remain exact and reject foreign, disabled or duplicate rules.
