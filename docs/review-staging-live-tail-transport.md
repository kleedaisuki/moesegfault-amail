# Staging live-tail transport: independent review

Status: static review of commit `9762cb9` on 2026-09-29. No local tests, Cloudflare Tail session, address mutation, or workflow invocation were performed. The adapter is uninvoked; none of the findings below implies an observed production data leak. The reviewer inspected the transport, synthetic tests, parser/prototype notes, and Cloudflare's official Wrangler Tail implementation and filter types.

## Required corrections before hosted testing or operational wiring

1. **Blocker — module cannot import.** `infra/tests/staging_live_tail_transport.py:54,87` uses `except Exception from None:` and `except ValueError from None:`. Python permits `from None` on `raise`, not on an `except` clause. Any import or test collection of this module fails before the synthetic tests can run. Change these to ordinary `except` clauses; preserve content-free `raise TailTransportError(...) from None` inside the handler. Add an import/compile smoke test to hosted CI.

2. **High — cancellation or first DELETE failure can leave a Tail running without a retry.** In `TailSession._close()` (`infra/tests/staging_live_tail_transport.py:201-226`), `_closed=True` is set before awaiting reader cancellation and socket close. If the enclosing task is cancelled at either await, the subsequent `__aexit__()` call sees `_closed` and returns while `_tail_id` still exists, never attempting the server DELETE. Similarly, a failed DELETE leaves `_closed=True` and `_tail_id` intact, but the later `__aexit__()` cannot retry. This violates the adapter's exact-delete contract and can leave a sensitive tail session live until expiry. Make closure/deletion an idempotent state machine keyed by *confirmed deletion*, not attempted closure; make the critical delete run to completion despite caller cancellation, and expose fixed cleanup failure to the owner if confirmation remains unavailable. Add synthetic tests for cancellation during both awaits and a transient first DELETE failure. `__aenter__()` also masks cleanup failure under `transport_unverified` after a failed handshake; distinguish the fixed cleanup-failed state without revealing provider exception text.

3. **Medium, protocol parity — the stream may never start.** The [official Wrangler Tail client](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/tail/createTail.ts) sends a text `{"debug":false}` message immediately after WebSocket `open`, whereas `TailSession.__aenter__()` only connects and begins receiving. The source calls this a filters/debug message; it does not establish whether it is strictly required by the server. A connection plus `trace-v1` subprotocol therefore does not establish that the adapter has completed the producer's expected handshake. Mirror the fixed, non-sensitive initial message or verify against a disposable Tail session before claiming the transport is operational; assert the message in synthetic tests. This is a possible availability/false-readiness issue, not proof of a leak or of effective POST filtering.

## Boundaries that appear sound at source level

- Tail create targets exactly the named staging Worker, using the [official method filter shape](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/tail/filters.ts) `{"filters":[{"method":["POST"]}]}`. The response `id` is constrained before it can enter a DELETE path; the WebSocket URL must use `wss`, without userinfo, fragment, or non-443 port. The HTTP response and each frame have caps; raw frames remain in process and go to a separately reviewed fail-closed parser.
- API/network exception strings and HTTP response bodies are not intentionally printed or returned. A private WebSocket URL, token, Tail ID, request ID, or raw event does not appear in a normal result label. The use of a dedicated logger with propagation disabled reduces accidental library logging, but operational logging configuration still needs review.
- `connected()` is not called `observer_ready`; it proves neither the effective server filter nor lossless delivery. The parser also checks POST locally and requires exact CLI-derived request-ID binding before a positive classification. These are appropriate fail-closed boundaries, but no actual Tail event shape has been validated online.

The [Cloudflare Tail API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/tail/) documents the create/delete resource; [Cloudflare real-time logs](https://developers.cloudflare.com/workers/observability/logs/real-time-logs/) and Wrangler source are the protocol evidence. An official online disposable Tail handshake is the next discriminating probe *after* the syntax and cleanup fixes, not an address-add attempt.
