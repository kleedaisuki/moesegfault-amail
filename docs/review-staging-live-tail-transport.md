# Staging live-tail transport: independent review

Status: static review of commit `9762cb9`, updated after fix commit `9041d1f` on 2026-09-29. No local tests, Cloudflare Tail session, address mutation, or workflow invocation were performed. The adapter is uninvoked; none of the findings below implies an observed production data leak. The reviewer inspected the transport, synthetic tests, parser/prototype notes, and Cloudflare's official Wrangler Tail implementation and filter types.

## Required corrections before hosted testing or operational wiring

1. **Resolved at source level in `9041d1f` — module import syntax.** The invalid `except ... from None` clauses are now ordinary `except` clauses, while content-free `raise TailTransportError(...) from None` remains. Hosted CI has not yet run this revision.

2. **Partially resolved in `9041d1f`; remaining high-priority cleanup disclosure.** `_closed` was removed; `_close()` now attempts a bounded synchronous DELETE in `finally` even if awaited socket close is cancelled, and retains `_tail_id` after a failed DELETE so a later exit can retry. The synthetic test covers one cancellation during close. However, `__aenter__()` still ignores `_close()`'s `False` after a failed handshake or initial control-frame send, then raises only `transport_unverified` (or propagates cancellation). If DELETE also fails, the caller cannot distinguish a still-live sensitive Tail from an ordinary handshake failure. Prefer a fixed `transport_cleanup_failed` signal when deletion remains unconfirmed; cover a failed first DELETE followed by successful retry and a persistent failure in synthetic tests. Operational wiring must treat every unconfirmed deletion as an owner cleanup incident. The revised cancellation path appears to handle a *single* cancellation statically; it is not evidence against repeated cancellation or process kill.

3. **Resolved at source level in `9041d1f` — protocol parity.** The adapter now sends the fixed non-sensitive `{"debug":false}` text message after the `trace-v1` upgrade and before marking the observer connected; a synthetic test asserts the message and a failure test checks cleanup. This still does not prove the server accepted the filter or that any event will be delivered.

## Boundaries that appear sound at source level

- Tail create targets exactly the named staging Worker, using the [official method filter shape](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/tail/filters.ts) `{"filters":[{"method":["POST"]}]}`. The response `id` is constrained before it can enter a DELETE path; the WebSocket URL must use `wss`, without userinfo, fragment, or non-443 port. The HTTP response and each frame have caps; raw frames remain in process and go to a separately reviewed fail-closed parser.
- The [official Start Worker Tail schema](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/tail/methods/create/) declares `result.id` maxLength 32 and illustrates a 32-character hex ID. The adapter's `[A-Za-z0-9_-]{1,32}` accepts that documented shape; a 36-character UUID concern is not supported by the current API contract. This verifies shape compatibility only, not a live session's behavior.
- API/network exception strings and HTTP response bodies are not intentionally printed or returned. A private WebSocket URL, token, Tail ID, request ID, or raw event does not appear in a normal result label. The use of a dedicated logger with propagation disabled reduces accidental library logging, but operational logging configuration still needs review.
- `connected()` is not called `observer_ready`; it proves neither the effective server filter nor lossless delivery. The parser also checks POST locally and requires exact CLI-derived request-ID binding before a positive classification. These are appropriate fail-closed boundaries, but no actual Tail event shape has been validated online.

The [Cloudflare Tail API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/tail/) documents the create/delete resource; [Cloudflare real-time logs](https://developers.cloudflare.com/workers/observability/logs/real-time-logs/) and Wrangler source are the protocol evidence. An official online disposable Tail handshake is the next discriminating probe *after* the syntax and cleanup fixes, not an address-add attempt.
