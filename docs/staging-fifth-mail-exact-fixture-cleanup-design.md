# Fifth hosted E2E: guarded exact-fixture cleanup fallback

Status: **guarded implementation prepared; first dispatch failed before preflight** for [run 36589042183, attempt 1](https://github.com/kleedaisuki/moesegfault-amail/actions/runs/36589042183). The manual `staging-fifth-mail-cleanup` CI target runs `infra/tests/staging_fifth_mail_cleanup.py` only with confirmation `DELETE_FIFTH_MAIL_EXACT_FIXTURES`, the literal run coordinates, and a reviewed 100%-serving Worker version UUID. It does not create an address, route, or SMTP message. The [first cleanup dispatch 36598713065](https://github.com/kleedaisuki/moesegfault-amail/actions/runs/36598713065) emitted `fifth_cleanup_failed:version_unverified` before `fifth_cleanup_preflight`; no authenticated CLI, delete, D1 mutation, SMTP, route change, or new address occurred in that attempt. Source review found that its in-process serving-pin call could not import the sibling privacy checker because the import path was installed only by `pin_staging_mail.py`'s `__main__` entry. This is a harness import failure, **not evidence of serving-version drift**. The pin now resolves its sibling from its own file location in both direct and in-process invocation, with a synthetic regression test; hosted CI and any subsequent guarded dispatch are separate evidence. The [original mail incident](staging-fifth-mail-sync-409-incident-36589042183.md) remains a failed acceptance run even after successful cleanup.

The implementation accepts an idempotent partial/complete soft-deleted state only if the fresh exact D1 aggregate still accounts for exactly one Signal and one Distractor in total, no other or outbound mail, the exact route is absent, and the retired expected-issuer address is reconciled. It compares the complete owner-scoped CLI inventory with active aggregate counts before each deletion. A successful CLI login plus this agreement is **not** proof that the address `owner_sub` equals the authenticated principal, nor proof of global foreign-owner absence: the aggregate excludes foreign-owner messages by its join. The stronger private operator attestation described below remains the preferred gate if available. Absent that attestation, dispatch is an explicit risk acceptance limited to these exact two owner-visible fixtures, not a claim of global absence. The script also requires exact submitted Message-ID rather than waiving an unexplained rewrite; if the provider changed it, cleanup stops for independent provenance review.

Only syntax and diff inspection were performed while preparing this change; the synthetic tests were added for later CI execution but were not run locally. The final post-delete gate allows a deleted fixture bucket to be 0 or 1 because Cron may physically purge a soft-deleted row. It still requires every active, unrelated, and outbound bucket to be zero; it does not claim physical erasure.

## Decision gate after the aggregate

| Aggregate result | Decision |
| --- | --- |
| Route absent, exact D1 address `retired` with `needs_reconcile=0` and expected issuer; all inbound/outbound active counts zero | **No cleanup.** Deleted fixture buckets are historical soft deletes, not active mail. Retain audit evidence; no new probe. |
| Same route/address/owner gate; `other_inbound_*` and `outbound_*` all zero; each Signal/Distractor total (active + deleted) at most one; at least one fixture active | **Conditional go for a separately reviewed, agent-owned hosted CLI cleanup**, subject to the stronger pre-delete checks below. The aggregate's `owner_expected` checks issuer only, so it is not by itself an exact-principal attestation. |
| Any read/shape failure, route present, address absent/mismatched/not retired, `needs_reconcile=1`, other mail, duplicate fixture, or bucket `more` | **No-go.** Resolve ownership, route, or ambiguity privately before any message delete. A successful aggregate exit code alone is not a go signal. |

The `other_inbound_deleted` bucket is also a no-go: it is evidence that this address received mail outside the two known fixtures, even if that mail is no longer visible to the CLI. Require a private reconciliation rather than silently treating a matching title as ownership. If the aggregate is zero for both fixtures, the right conclusion is *no active fixture observed*, not proof that SMTP never persisted a message.

Before promoting the conditional go to an actual delete, extend the **read-only preflight** with a restricted Identity/D1 operator's private boolean attestation that the exact D1 address `owner_iss/owner_sub` equals the authenticated synthetic principal, and a count of **all** messages at the exact address whose owner pair differs from that address owner. Neither raw principal value nor message row may enter logs. Do not extract or print native CLI tokens to manufacture this attestation. The current aggregate joins only messages belonging to the address owner, so it cannot itself rule out foreign-owner rows at the same address. Any failed attestation or nonzero foreign-owner count is a no-go, even if the current aggregate and CLI inventory otherwise appear to agree.

### Search consistency and privacy rules

`search_job_stale` (HTTP 409) may be retried **only for the read-only search**, from a fresh first page, at most twice with bounded delay (e.g. 2 s then 5 s). Treat `search_cursor_stale` similarly, discarding the entire partial pagination snapshot; never combine pages from different generations. Resume an already accepted search job privately using its job ID instead of resubmitting while it is running. Any third stale outcome, persistent/unknown 409, 429, 5xx, timeout, incomplete page, or unclassified CLI failure is a no-go, not an empty result. The same bounded policy applies to post-delete readback, but a readback failure must report cleanup **unverified** rather than prompting a second mutation. Avoid concurrent account/mailbox probes during the narrow cleanup window; indexing may still mutate search generations.

Capture raw CLI stdout/stderr only inside the protected process. Parse only allowlisted status/code and expected JSON shapes; never echo raw subjects, aliases, message IDs, search cursors/job IDs, bodies, ZIPs, auth codes, tokens, or raw provider responses to Actions logs, diagnostics, or artifacts. Set `AMAIL_TELEMETRY=off` for this operation, recognizing that this does not disable background embedding. The generated nonce and submitted Message-ID are **locators, not authentication**: anyone able to see or copy a mail can spoof headers and subject. The multiple independent checks reduce accidental deletion risk, but only a trusted provenance record can resolve an adaptive same-title/same-header spoof. If such a record is unavailable when ambiguity exists, fail closed and leave the message for restricted manual review.

## Why this is not the existing cleanup

`staging_mail_e2e.py::cleanup_run` uses a single `sync --limit 100` page and title equality. That is incomplete for an old run and cannot distinguish a forged same-title message. Search plus exact mailbox scoping, complete pagination, account/D1 agreement, `get` corroboration, single-ID deletion, and readback replace that unsafe shortcut **for this fallback only**. The Worker currently scopes `get`/`delete` by `(owner_iss, owner_sub)` and marks `deleted_at`; its Cron later purges deleted rows. Cloudflare documents that D1 queries outside its Sessions API read from the primary, which supports the separate control-plane aggregate as a current readback, but the route audit and CLI observations are still separate systems and must agree: [D1 read-replication guidance](https://developers.cloudflare.com/d1/best-practices/read-replication/).
