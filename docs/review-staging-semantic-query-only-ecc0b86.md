# Review: no-SMTP semantic query discriminator (`ecc0b86`)

**Decision: GO for hosted CI, then one guarded staging dispatch; not a semantic-search acceptance result.** This is an independent source review of the manual workflow, Python harness and mock tests. I did not run local heavy tests, authenticate, query OpenRouter, dispatch Actions or mutate mail.

## Safety and contract trace

- The new job is `workflow_dispatch`-only, limited to `main` or `codex/amail-v0.1.0`, requires the exact `RUN_STAGING_SEMANTIC_QUERY_ONLY` confirmation, and shares `staging-native-mail-acceptance` with SMTP E2E. The job supplies only the two synthetic Identity secrets to the probe step; no SMTP, Routing, D1 operator, or Cloudflare API token is passed. Its own Python environment check repeats the confirmation and requires GitHub run coordinates before native login.
- Credentials are popped from the parent environment before the Chrome/CLI children are launched. The existing native PKCE helper writes a same-user DPAPI blob under a fresh `.temp` run directory, sets staging issuer/client/API coordinates and telemetry-off, verifies the CLI session across processes, and closes the browser and listener. The new wrapper removes the entire exact run directory in `finally`; it never invokes address creation, SMTP, send, mark or delete. A failure in cleanup is reported as a fixed label.
- The inventory call is an unfiltered owner-scoped `search --limit 100`. `search_page_query` binds owner issuer/sub and filters `deleted_at IS NULL`. A complete empty result produces zero CLI JSONL lines. Contrary to an initial concern, `emit_items` **does emit** a non-null `next_cursor` as a JSONL object even when there are no message rows; `not jsonl(stdout)` therefore rejects a continuation. `run_search` emits stdout only for a complete response, so a running/failed job cannot masquerade as an empty successful inventory. This proves an empty *active owner-visible* snapshot at the inventory request, not an atomic exclusion of subsequent inbound delivery.
- The semantic call uses one fixed synthetic query only after that inventory gate. The Worker source creates an owner-scoped job, reserves quota and calls `platform::embed(..., "search_query")` before scanning the empty corpus. Its embedding client calls OpenRouter for a 256-dimensional vector. A successful empty result can validate current query embedding/job plumbing **only when the 100%-serving staging Mail Worker is pinned to the reviewed source**. It cannot validate document indexing, ranking, cosine, filter composition, or the historical failure cause.
- All CLI stdout/stderr are captured in memory with subprocess deadlines and size caps. The printed success/failure labels are source-owned and bounded; the typed classifier retains only an allowlisted HTTP status/code and POST-versus-poll phase, not the query, job ID, result, address, provider body, token or correlation ID. Unknown stderr becomes an unclassified fixed label. The mock tests cover the major gates and classifier shapes, but are not deployment evidence.

## Material limits and dispatch conditions

The `staging-native-mail-acceptance` group prevents simultaneous use by the matching E2E job, not by all possible staging deployments or external mail arrivals. The documented immediate serving-version readback is therefore an operational precondition, not a guarantee enforced by this job. If a deployment races the pin, report only observed API behavior; do not claim that OpenRouter was exercised by the reviewed Worker revision. A new inbound message between the inventory and semantic requests could likewise make the semantic result fail its empty-result assertion; this is fail-closed for the probe's stated claim, not evidence of a semantic defect. Search still writes quota/job state and can incur one provider charge; local-directory cleanup does not roll back those server-side effects.

Do not dispatch until this revision's hosted infrastructure tests and Windows CLI build are green and the Mail Worker version has been freshly pinned. Dispatch once; preserve only checkout SHA, pin/run IDs and fixed outcome label. A passing empty-corpus probe is a **narrow current-path discriminator**, never a substitute for a later guarded two-fixture semantic acceptance run.
