# Offline staging live-tail observer prototype

Status: **offline parser plus uninvoked transport adapter; not an operational observer or address-add authorization** (2026-09-29). The files `infra/tests/staging_live_tail_observer.py` and `infra/tests/test_staging_live_tail_observer.py` provide a bounded, in-memory parser and synthetic hostile fixtures. The separate `infra/tests/staging_live_tail_transport.py` implements the fixed Worker Tail API/WebSocket lifecycle but is not imported by a workflow or invoked online. Its synthetic transport tests use an injected fake socket and fake API. No tail session, deployed Worker query, route mutation, mail send, address create, or hosted E2E has been run for this adapter. Local tests have intentionally not been run; GitHub CI remains the verification venue.

## Why this boundary exists

The [second address-add incident](staging-address-add-incident-36533465672.md) remains historically **UNVERIFIED**. A future, separately approved attempt may benefit from observing the already instrumented `addresses_add` `routing_list`, `routing_create`, and `request_exit` events. Cloudflare's [real-time logs documentation](https://developers.cloudflare.com/workers/observability/logs/real-time-logs/) shows an invocation envelope with `outcome`, `scriptName`, `exceptions`, `logs`, `eventTimestamp`, and `event.request`, including URL and headers; it also warns that high-volume tails can sample and drop logs. Its [Wrangler tail documentation](https://developers.cloudflare.com/workers/wrangler/commands/workers/#tail) offers filtering but not a lossless-delivery guarantee. The parser therefore never looks at or emits the URL, headers, exception text, or raw console strings. A missing event, warning, sampling signal, disconnect, or unknown shape cannot be used as proof that a provider POST did not occur.

| Layer | Current contract | Remaining gate |
| --- | --- | --- |
| Worker | Schema-v1 `mail_api` events with fixed operation/phase, opaque causal IDs and numeric provider status/code; no provider text slot | Deployed version and privacy settings must be verified privately |
| Tail envelope | Exact `scriptName == amail-mail-staging`, POST invocation, `outcome == ok`, reviewed console JSON only; URL/headers are ignored | Confirm the actual WebSocket output shape; Cloudflare's example permits `scriptName: null`, which this parser deliberately rejects |
| Parser | 64 KiB/frame, 2 MB total, 200 frames/events, 600 seconds; one root, coherent phase order, and exact private CLI-derived request-ID binding at `finish`; fixed labels only | Independent hostile-fixture review and GitHub CI |
| Transport | Uninvoked owner-only `TailSession` adapter requests the exact staging Worker with POST method filter, validates `trace-v1` WebSocket upgrade, caps inbound frames and session lifetime, consumes raw frames in memory, and deletes the exact Tail in `finally` | Independently review and hosted-test adapter; operational caller must still do privacy preflight, CLI request-ID binding, route cleanup and mutation isolation |
| Mutation | **Not implemented** | The incident's isolation, Worker credential, readiness, explicit approval, and cleanup gates all remain required |

The parser and transport intentionally **never emit `observer_ready`**. The adapter's successful entry means the Tail create call included the POST filter and a `trace-v1` WebSocket opened. Cloudflare's API and Wrangler source do not provide a separate acknowledgement that the filter became effective, so this is **configured and connected, not filter-effective proof or E2E readiness**. The parser still rejects non-POST frames locally. No address attempt should be released solely because the socket connected. Do not point the module at `wrangler tail` stdout: Wrangler may print status/warning lines outside the JSON stream.

## Fixed output and causal interpretation

The only completed-chain labels are `routing_list_failed`, `routing_create_failed_provider_http_<100–599-or-absent>_code_<0–4294967295-or-absent>`, `routing_create_succeeded_later_failure`, and `e2e_address_add_succeeded`. Every other result is `UNVERIFIED (<fixed reason>)`. A positive classification requires an exact privately obtained `expected_request_id` at `finish()`, matching the single observed server root. This binding must come from the authorized CLI's captured response or stderr `correlation_id` after that call returns, **not** from a request URL, address, or the observed tail itself. The current harness does not supply that binding to an observer; the future runner must implement and review it before a hosted attempt. An absent, malformed, or mismatched ID yields `UNVERIFIED`. The numeric values are schema-bounded; provider messages, request and trace IDs, addresses, routes, session IDs and URLs never enter a label. Even a `200` provider status can accompany a `routing_create` phase failure, so the event's outcome controls classification. A successful add speaks only to that future attempt, not either historic failure.

The parser rejects non-JSON console strings, duplicate JSON keys, unknown event fields, producer-impossible field combinations, malformed identifiers, duplicate roots or spans, unrelated trace IDs, missing list phase, inconsistent event order, unexpected service, sampled frames, nonempty exception/diagnostic arrays, raw/unreviewed envelope shapes, overflow, unbound provenance, and an unclean finish. The server root may legitimately have an authenticated CLI parent span; each routing child must name the server root span. It consumes complete frames in memory and retains only the small validated event projection. This deliberately sacrifices availability for a narrow privacy and attribution boundary. It cannot detect **silent** provider-side sampling or drops, so even a syntactically complete causal chain should be described as “observed live-tail classification,” never as a guarantee that all emitted events were delivered. A full runner must mark any visible warning or transport anomaly via `lost()`.

## Uninvoked transport adapter and future secure runner

The [Cloudflare Tail API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/tail/) defines create and delete on a named script; the [Wrangler implementation](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/tail/createTail.ts) sends the filter JSON in the create POST body and requests the `trace-v1` WebSocket subprotocol. Its [filter type](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/tail/filters.ts) makes the exact method filter `{"filters":[{"method":["POST"]}]}`. The adapter reproduces only that narrow protocol, with no Wrangler process and no raw stdout. It requires `websockets==17.1` only if actually used online; synthetic tests inject a socket and need no package. The [websockets client API](https://websockets.readthedocs.io/en/latest/reference/asyncio/client.html) supplies bounded `max_size`, `max_queue`, handshake/idle timeout and ping controls. Before operational use, pin the dependency in a reviewed owner-side environment and verify the API response shape against a disposable Tail session without touching mail routes.

Conceptual use by a **separately reviewed** owner-only runner (not an executable recipe for a new E2E):

```python
async with TailSession(account_id, tail_read_token) as tail:
    # Only after independent privacy/isolation gates: run one authorized CLI call.
    # Derive request_id privately from that CLI response, then finish its cleanup.
    label = await tail.finish(expected_request_id=request_id)
```

`TailSession.finish()` returns only a fixed parser classification, and only after confirmed session deletion. It does not display raw frames, URL, headers, exceptions, API bodies, token, session ID, request ID, or trace ID. A delete failure overrides even a positive causal result with `UNVERIFIED (transport_cleanup_failed)`. The raw frame limit is 64 KiB; transport queue length is one; parser limits aggregate bytes, frames, events and 600 seconds. The adapter has no CLI subprocess, address creation, deployment, CI wiring or user-visible command. It does **not** prove that Cloudflare applied the filter, did not silently sample, or delivered every event. It never turns absence into evidence of no provider POST.

1. Run only in a restricted, ephemeral **owner-side** process with no shell tracing, job-step raw log capture, artifacts, `tee`, debug logging, or credential inheritance into the mail CLI. Pin and review any WebSocket client dependency and its log behavior. Install it only inside an ignored workspace `.temp` or CI environment, never in a shared untrusted agent image. Keep credentials in protected secrets, not arguments or URLs printed by the runner.
2. Privately verify the deployed staging Worker's privacy configuration with the existing `check_observability.py` path and the exact intended Worker version. Provision a token scoped to this one account/Worker with **Workers Tail Read**; the [Tail API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/tail/methods/create/) also accepts **Workers Scripts Write**, but that broader permission is not appropriate. Confirm token restrictions, expiration, and owner audit. Do not reuse the mail Worker's Routing Rules write credential for observation.
3. Start only `POST /accounts/{account_id}/workers/scripts/amail-mail-staging/tails` with the POST-method filter body. This creates a Tail control-plane session, **not** a Routing Rules POST. Do not list or tail unrelated Workers. The API returns a sensitive WebSocket `url`, `id`, and `expires_at`; never display or persist them. Verify the actual `trace-v1` upgrade and local non-POST rejection. Because the create response does not echo effective filter state, do not call the socket an `observer_ready` attestation; the filter is a volume guard, not the privacy trust boundary. If handshake, privacy preflight or previous-run isolation is absent, **do not dispatch E2E**.
4. During the one approved window, forward complete bounded text frames directly into `feed()`. Treat binary frames, partial/truncated frames, warning/control messages, sampling, transport reconnection, backpressure loss, timeout, or disconnect as `lost()`. Privately extract the server request ID from the authorized CLI's captured response or stderr after its address call, validate its UUID shape, and pass it only in memory to `finish(expected_request_id=...)`; never infer identity from an address, URL, or tail record. Keep the session alive through the harness's seven-minute exact-route/CLI cleanup readback. Do not infer “no provider POST” from a missing create event.
5. In `finally`, close the WebSocket and call `DELETE /accounts/{account_id}/workers/scripts/amail-mail-staging/tails/{id}` using the same restricted token, suppressing raw exception/body text. Failure to confirm deletion is a fixed `UNVERIFIED` cleanup failure requiring private owner action. The runner should have a hard wall-clock deadline and terminate without leaking traceback or HTTP error content. A clean parser `finish()` is allowed only after orderly transport stop **and** confirmed session deletion and harness cleanup; otherwise `clean_end=False`.

Before wiring any shared workflow or permitting a new address attempt, review and offline-test the real transport's readiness, warning, sampling, disconnect, cleanup and duplicate-root behavior independently. The [incident decision gates](staging-address-add-incident-36533465672.md#decision-gates-before-one-more-mutation) remain controlling: isolate the two previous run-owned aliases and D1 state, inspect the **deployed Worker** Rules Read/Write credential, obtain explicit owner approval for one exact run, and freeze on any ambiguity. This prototype is preparation, not approval to create a third address.
