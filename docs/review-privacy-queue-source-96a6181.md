# Independent review: private Queue trace source and sink

Date: 2026-09-30. Scope: `96a6181` with corrective follow-up `728f2c3`,
the contract in `ada53db`, surrounding API callers, shared schema, source
observability checker/configuration, locked SDK and pinned bundler source.

## Decision

**GO for GitHub-hosted compilation and synthetic boundary testing. No substantive
source defect was identified within this scope. This is NOT live rollout approval,
privacy acceptance, guaranteed event retention, or whole-project completion.**

No local test/build, Cloudflare query, deployment, queue mutation, or production
implementation modification was performed. The review does not certify the
separately changing deployment workflow, resource provisioner, retained-record
canary, or role-monitor implementation.

## Evidence-backed assessment

| Concern | Source evidence and assessment |
| --- | --- |
| Public invocation retention | Both explicit realms in `crates/mail-worker/wrangler.toml` disable parent observability, Logs and Traces. No `console_*` call remains in this crate's Rust sources. `check_observability.py` requires this boundary and rejects script exports/tail consumers. The deployed settings still require independent readback. |
| Request ownership / post-response lifetime | `src/lib.rs:136-158` clones Env for dispatch, records the final event, detaches owned events, then moves only Env/events into `Context::wait_until`. The request, auth object, arbitrary headers and response body are not captured. `RefCell` borrows are short synchronous borrows, not held across an await. |
| Failure isolation | `trace.rs:548-557` drops diagnostics on missing binding or failed enqueue; it cannot return a new business error, log unsafe fallback data, or replay a mail operation. Later unsent chunks may be lost after a failed chunk. This is the explicitly chosen best-effort contract, not durable producer delivery. |
| Memory / transport limits | `trace.rs:258-270` validates before buffering, bounds each encoded event to 1,024 bytes, caps ordinary events at 127 and reserves slot 128 for exit. `queue_batches` caps each call at 100 messages; at most 100 KiB of serialized event bodies is far below the 256-KB send-batch bound. SDK overhead/temporary serialization increases memory by a bounded amount, not an unbounded mail payload. |
| Full CLI upload | The accepted wire batch remains capped at 100. The test source exercises 100 client rows plus API exit, expecting 100+1 submission chunks, retained event IDs, and saturation/exit reservation. Submission order is preserved; Queue delivery order is **not** guaranteed and readers must not infer causality from log order. |
| Schema privacy boundary | `crates/trace-schema/src/lib.rs` uses closed enums, `deny_unknown_fields`, exact canonical nonzero W3C IDs, canonical RFC4122 UUIDv4, bounded power-of-two/time/status values, and service/phase-specific field combinations. Invalid JSON-compatible objects are not forwarded. The sink reserializes the decoded Event, not the original payload or error. Numeric provider codes remain bounded `u32`, not text. |
| Follow-up invariant corrections | `728f2c3` restricts CLI service operations to the actual historical CLI vocabulary, requires RFC4122 UUID variant, and classifies 1xx consistently as success. Legacy status zero remains an accepted CLI server-error class. Invalid historical correlation IDs can be omitted from retained events without changing public telemetry acceptance. |
| W3C parentage | Auth precedes `accept_parent` for public user routes; inbound uses its existing trusted internal authentication boundary. Request exit retains original server span/CLI parent. Phase spans have fresh span IDs and parent the server span. Queue event IDs are added correlation handles, not replacements for business trace/span/request IDs. Maintenance events intentionally do not fabricate a common Cron parent. |
| Warning parity | Eight scheduled failure labels, three routing reconciliation labels, two embedding failure labels, and the storage-ledger label map to fourteen closed `DiagnosticCode` values. The two ledger request sites use causal buffered warnings. Cron/nested reconciliation sends are awaited best-effort operations with standalone maintenance IDs. They add bounded operational latency, not another mail/auth API contract. |
| Poison handling | `workers/trace-sink/src/lib.rs:16-35` iterates raw messages so one decoding failure does not abort typed batch decoding. Decode/semantic-validation failure calls raw `ack()` and continues without error/body logging. A valid event serialization failure calls individual `retry()`, then continues; successful events log safe reconstructed JSON then acknowledge. |
| Stable redelivery identity | `event_id` is generated by the producer, serialized into Queue payload and not regenerated by the sink. At-least-once redelivery may duplicate a log with the same ID. No claim is made that console logging followed by ack proves retained delivery. |
| Sink capabilities | Rust exports only a Queue handler. Both realms disable Workers.dev/previews, have no HTTP route, Cron, mail, business storage, service binding or extra producer. Consumer retries/concurrency are finite. Existing unreviewed deployed routes/settings remain a rollout-readback concern, not proven absent by this file alone. |

## Pinned runtime/API compatibility

`Cargo.lock` resolves `worker` 0.8.7. Its official source has
`Env::queue`, `BatchMessageBuilder::messages`, generic `Queue::send_batch`,
`MessageBatch::raw_iter`, `RawMessage::body` and `MessageExt::ack/retry` with
the used signatures. `Context::wait_until` requires an owned `'static` future
whose output is `()`, matching the detached producer handoff. All event integers
crossing the JS serialization boundary are at most 2^32, so this schema does not
depend on JS Number representing arbitrary u64 values exactly.

Pinned `worker-build` 0.8.5 generates handlers from actual Wasm-bindgen exports;
it does not intentionally synthesize a fetch handler for a Queue-only crate.
The generated artifact must nevertheless be inspected in hosted CI. Its runtime
shim includes generic critical-Wasm-error/reinitialization console paths, and
the Queue macro logs returned `Err` values. The reviewed Queue handler always
returns `Ok(())` for handled poison and uses no arbitrary returned error; that
does not prove all future panics/runtime failures safe. Built-boundary exception
tests and complete retained-event validation must cover this distinction.

## Required evidence before live rollout / acceptance

These are outstanding verification obligations, not invented source defects:

1. GitHub-hosted Rust tests, both Wasm builds, generated-handler checks, and a
   real built workerd Queue boundary test. Exercise malformed/raw/nested bodies,
   unknown fields, invalid identifiers, legacy rows, numeric/status combinations,
   two-chunk full telemetry, buffer saturation and controlled enqueue refusal.
   Assert unchanged business responses and no public console fallback.
2. Built sink tests must verify poison per-message ack/drop, safe valid logs,
   stable same-ID redelivery and per-message retry behavior, without logging raw
   poison or arbitrary error strings. Merely testing `Event::from_value` is not
   evidence about Queue glue or ack behavior.
3. Dedicated staging Queue/DLQ ownership, independent 24-hour retention readback,
   consumer settings/capability/exposure readback, sink-first deployment and
   producer/sink exact serving-version pins. No producer deployment before the
   required sink/resource gate succeeds.
4. One fresh bounded whole-record retained-data gate across source and sink,
   preserving original authenticated parentage and all required safe events
   while excluding path/query/address/body/header markers in **every** platform
   carrier. Logs docs are evidence for the containment design, not a guarantee
   against Queue message or original producer enrichment.
5. Retry/DLQ behavior remains finite; no automatic ambiguous replay. Keep the
   privacy-preserving rollback (source retention stays off), even on diagnostics
   failure. Production and public sending remain held for their separate gates.

Syntax validation cannot prevent a malicious authenticated caller encoding
information in an otherwise valid trace ID. The ADR explicitly preserves that
existing correlation trust decision; this review does not claim zero covert
channels. Likewise, API Queue containment does not certify Email/Cron role-mail
observability or all other services.
