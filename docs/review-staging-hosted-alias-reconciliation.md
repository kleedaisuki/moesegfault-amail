# Review: one-run hosted alias reconciliation

Scope: the uncommitted `infra/tests/staging_hosted_alias_reconcile.py`, its synthetic tests, `docs/staging-hosted-alias-reconciliation.md`, and only the `staging-hosted-alias-reconcile` input/job additions to `.github/workflows/ci.yml`. Static review against the existing historical-alias reconciliation, native hosted E2E HMAC derivation, and workflow secret scoping. No local test, network request, or provider mutation was performed.

## Assessment

**No remaining substantive blocker found for the read-only manual target.** The script uses the same v1 HMAC-SHA256 message and 16-hex suffix as `staging_hosted_e2e.py::recoverable_run_nonce`, with the protected synthetic password and explicit GitHub run ID/attempt. It derives only one address and keeps it out of output. It reuses the historical gate's bounded, page-complete Routing Rules GET and its fixed parameterized staging D1 `SELECT`. The D1 API call is HTTP POST, but executes only that read-only SQL. No mail, address, route, SMTP, or deployment mutation is reachable from this target.

The first draft accepted a 4–5 digit attempt even though the hosted E2E rejects attempts longer than three digits. Such an input could have reported `clean` for an address that the referenced run could never have created. The implementer narrowed both Python and PowerShell preflight validation to 1–3 digits and added a synthetic `1000` rejection case. Bad confirmation or malformed coordinates are now rejected before credentials or network reads. The original three-dimensional gate is preserved: an exact literal `to` rule is absent, the staging D1 address is absent or reconciled/retired with expected issuer, and both independent reads are verified; otherwise only `not_clean` or `unverified` is printed. The target does not weaken or replace the separately passing two-prior-alias gate.

The workflow keeps protected secrets in its final read step, not a job-wide environment, and has only the top-level `contents: read` GitHub permission. The script prints fixed route/row/gate labels and suppresses provider exception text, query values, identities, aliases, and credentials. Its separate read attempts preserve a known dirty result when the other control plane is unavailable. The synthetic tests cover clean and dirty results, independent failures, no alias/error leakage, and wrong-coordinate rejection.

## Limits and dispatch boundary

This is source-only review. CI has not yet validated the uncommitted revision, and a real provider read can still fail closed because of credentials, pagination shape, D1 shape, or availability. A `clean` result applies only to the HMAC address derived from the **operator-supplied** run ID and attempt at the time of read. This target cannot prove those coordinates refer to a completed hosted E2E, that an absent address previously existed, or that there are no wildcard routes; the operator must cross-check the exact GitHub run metadata and the existing prior-alias gate before dispatch. Passing does not diagnose the historical registration failures, establish Routing Rules Write permission, or authorize another mutation by itself.
