# Review: second-principal R2 inventory diagnostics (`eb14e23`)

**Decision: GO for the diagnostic-only source change; NO-GO for principal mutation on this evidence alone.** No substantive defect was found in the focused diff. This review did not invoke Cloudflare, dispatch a workflow, deploy, or inspect the private response body from hosted run 36695119073.

Cloudflare's [R2 List Objects API](https://developers.cloudflare.com/api/resources/r2/subresources/buckets/subresources/objects/methods/list/) marks `result_info` and its `is_truncated` member optional. Accordingly, absence is a valid documented response shape but **not evidence of a complete inventory**. `object_inventory()` still requires a boolean `is_truncated` before returning keys, and requires a nonempty, changed cursor for a truncated page. Missing metadata, malformed metadata, malformed entries/keys, and duplicate keys now produce distinct fixed labels. The implementation neither logs the response nor derives labels from provider-controlled strings. The read-only preflight continues to stop at inventory failure before B-contact classification; the registration route is opened only in `execute()` after `inspect_state()` and `preflight_contacts()` succeed.

The new mock cases cover empty responses with missing/malformed pagination, malformed result/entry/key, duplicate keys within and across pages, missing cursor, and one complete empty response. Locally, `PYTHONDONTWRITEBYTECODE=1 python -m unittest infra.tests.test_staging_second_principal -v` passed all 12 tests. The runbook correctly calls the prior aggregate failure inconclusive and does not infer a missing `result_info` from it; the new labels make one deliberate read-only retry more informative, not safe to bypass the inventory gate.

**Limit:** Tests use synthetic provider envelopes. Hosted CI and a deliberate read-only preflight are still needed to identify the actual R2 shape. A `r2_result_info_missing` outcome should prompt investigation of an alternative completeness proof or a documented compatible listing mechanism, rather than treating an empty `result` as complete and proceeding to mutation. The existing unrelated working-tree modifications were not reviewed or changed.
