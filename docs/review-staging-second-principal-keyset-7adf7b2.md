# Review: private R2 keyset inventory (`7adf7b2` + `1cb535a`)

**Source-review decision: GO for one deliberate, guarded, read-only preflight after hosted CI; NO-GO for principal mutation on source review alone.** No local tests, hosted workflow, Cloudflare request, push, or production change was performed in this review.

Cloudflare's [REST List Objects contract](https://developers.cloudflare.com/api/resources/r2/subresources/buckets/subresources/objects/methods/list/) makes `result_info` optional and defines `start_after` in lexicographic key order. The new `object_inventory()` uses fixed `prefix=verification/` and `per_page=100`, resumes after the last validated key, and continues through short pages until an empty page. It rejects non-list results, oversized pages, non-Worker UUIDv4 keys, duplicate or non-increasing keys, more than 1,000 objects, and scans exceeding 20 requests. The [Worker](../workers/identity-test-inbox/src/lib.rs) generates the same UUIDv4 key form. The source does not rely on optional cursors or interpret a short page as complete.

**Resolved blocker:** In `7adf7b2`, an empty `result` with `result_info.is_truncated=true` would have returned a supposedly complete inventory despite the provider's explicit contrary signal. This could have hidden a pre-existing object before route mutation or left a new object outside cleanup. Follow-up `1cb535a` rejects that contradiction with a fixed label, rejects malformed *present* `result_info`, and retains support for absent metadata; synthetic cases cover the contradiction and malformed shapes. No further substantive defect was identified in the reviewed path.

The read-only preflight calls `inspect_state()` and `classify_contact()` only: its source audits deployed settings, exact routes, D1 contacts, and R2 listing, without invoking registration, object GET/DELETE, or route apply/remove; `main()` emits only fixed labels. `execute()` still gates route creation behind inventory and contact preflight. `guarded_code()` and cleanup reuse the same bounded inventory and subtract the baseline, so an inventory failure stops retrieval or marks cleanup failed rather than silently accepting an incomplete scan. Cloudflare [documents strong consistency for individual R2 listings](https://developers.cloudflare.com/r2/reference/consistency/), but this multi-request walk is **not an atomic snapshot**: concurrent writes with keys before the current `start_after` can evade that pass. Route closure, serialized registration windows, re-audit before mutation, repeated polling, and final cleanup scans are therefore operational requirements, not proofs of an immutable inventory.

**Verification limit:** This is static source and contract review, not a test execution or a live-shape confirmation. Hosted CI and a single deliberate read-only dispatch are still required to establish that the actual REST response follows the documented keyset behavior and that the current token can list the private bucket. A green preflight does not establish object GET/DELETE permission or authorize B-principal provisioning by itself.
