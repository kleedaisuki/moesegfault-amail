## Contract

[`infra/provider/probe_staging_fourth_exception.py`](../infra/provider/probe_staging_fourth_exception.py) sends one `dry=true`, `view=events` Cloudflare Workers Observability query for `amail-mail-staging` and **2026-09-29 12:24:32–12:25:41 UTC**. It supplies no URL, alias, message, or dynamic search term as a query input; returned events may nevertheless contain such data. The response is bounded to 256 KiB and 200 rows, parsed only in memory, never written to disk, and never echoed. It rejects redirects, duplicate JSON keys, non-completed/non-dry runs, scope-echo mismatch, missing events, incomplete/truncated count, wrong service/script (including absent `$workers.scriptName`), and out-of-window timestamps. The sole output is one fixed `exception_result=` label. The exact opt-in input is `READ_FOURTH_STAGING_EXCEPTION_36567571204`; account ID and credential come only from environment variables. No GitHub workflow is wired to this probe; execute only in a private owner-side process after independent review and hosted synthetic tests. Do not enable shell tracing, raw HTTP logging, artifacts, or traceback capture. The tool cannot mutate routes, D1, Workers, or mail.

The classifier ignores `source`, `$metadata.message`, URLs, stack, and IDs. It examines only `$metadata.error` and `$workers.outcome` after scope validation. Only two exact static WebAssembly error literals are distinguished: `RuntimeError: unreachable`/`unreachable` and `RuntimeError: memory access out of bounds`/`memory access out of bounds`. Every other error string, including a string containing private content, maps to `other_or_absent`. A single candidate still ends `_not_attributed`; multiple candidates yield `multiple_exception_records_not_attributed`. No candidates yields `no_exception_record_not_absence_proof`, since automatic invocation logs are disabled and retention/sampling need not cover the failing request. Even a literal `unreachable` would establish only a retained exception *somewhere in the window*, not that Rust panicked or that `POST /v1/addresses` trapped.

This deliberately does **not** relax the full retained-log privacy canary or interpret an unreviewed `source` wrapper. The query itself receives potentially sensitive historical records in process memory, so execution is restricted to a trusted local operator; it is not suitable for a broadly visible GitHub Actions log. The **operation** is constrained to a dry, non-mutating query, but the [Cloudflare telemetry query API](https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/) requires a credential with **Workers Observability Write** permission. Do not describe that credential as read-only or assume dry mode limits its authority. The API also documents event view, service filters, event metadata, `$workers.outcome` and `$metadata.error`; [Cloudflare's exception guide](https://developers.cloudflare.com/workers/observability/errors/) documents the `exception` outcome and error-exists filter. Neither source guarantees that an exception event is retained when invocation logs are disabled. The [Cloudflare exception-enrichment changelog](https://developers.cloudflare.com/changelog/post/2026-08-24-preserve-exception-info/) warns that error records can contain exception messages and stacks, motivating the fixed-output boundary.
