# amail v0.3.1

Release notes: 2026-10-25 (Asia/Singapore). Actual backend delivery and formal
asset publication are recorded separately in the validation ledger.

## Default-off semantic search

Semantic search and its background indexing now use an account-wide opt-in switch,
**off by default for both new and upgraded accounts**. Ordinary literal searches
continue to work without transferring query text to an embedding model.

```sh
amail semantic status
amail semantic enable
amail semantic disable
```

Only the active `user` profile can enable or disable indexing. Each switch normally
opens a browser for human confirmation; an existing explicitly configured YOLO
setting retains its usual behavior. An agent profile cannot change the setting,
which affects all profiles in the account. Do not enable YOLO to bypass a privacy
decision. Concurrent switches bind the observed generation rather than silently
replaying an old decision.

After enablement, bounded background work indexes **all eligible retained mail**,
then eligible newly received and sent mail. Subjects and extracted body text,
bounded to 12,000 UTF-8 bytes, pass through OpenRouter to Voyage 4. Raw ZIPs and
attachments are not inputs. Semantic queries also cross that boundary. The approved policy
`voyage4_no_training_retention_v1` fixes the Voyage provider, disables fallbacks,
requests no training and disables response caching. It is **not zero retention**:
upstream may retain inputs/outputs for an unspecified period under its terms.
Neither disable nor mail deletion guarantees upstream erasure. Stricter account
privacy settings are not overridden to make the route available.

Disabling stops admitting new document/query provider requests, but **does not
delete stored document embeddings**. Already admitted provider requests cannot
recall transmitted bytes; stale results cannot publish. Re-enabling creates a
fresh full-index generation, including messages with retained vectors. It re-sends
mail text to compute new vectors, not old vectors as a model-conversion request.
Enabling an already-enabled account does not restart indexing.

## Existing embeddings and compatibility

A dedicated additive forward migration preserves existing embeddings, initializes
consent to off and prevents old work from silently re-sending mail. Qwen and Voyage
vectors are never mixed in a ranking. Retained embeddings only become usable after
successful re-indexing in the newly approved model/consent generation. Incomplete
background work is typed incomplete, never a falsely complete search result.

Telemetry preferences do not control semantic consent. Profiles, mailbox read/write
occupancy, ZIP contracts, JSONL output and unresolved send journals retain their
existing contracts. Keep original send keys and ZIPs across the upgrade. Stop old
CLI processes and any daemon before replacing binaries; install the CLI and Skill
from the same verified release. Do not infer deployment or sending authority from
these notes.
