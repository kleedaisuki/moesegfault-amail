acceptance and local installation are recorded separately in the

## Permanent mailbox acquisition

Fix the CLI rejecting a successful permanent-mailbox lease with
`invalid mailbox lease`. Permanent addresses intentionally have an empty
generation string; only recyclable temporary addresses need a distinct lifetime
generation. The CLI now preserves the server's opaque generation unchanged,
including the valid empty value, when saving an acquired lease locally.

```sh
amail mailbox acquire you@mail.moesegfault.dev --mode read
amail mailbox acquire you@mail.moesegfault.dev --mode write
amail mailbox release you@mail.moesegfault.dev
```

The commands apply only to an address already owned by the authenticated account.
Existing non-preemptible reader/writer arbitration, profile/session isolation,
opaque lease capabilities and temporary-address lifetimes are unchanged. Invalid
or missing capabilities and invalid modes remain rejected. Lease capabilities
are not printed in normal JSONL output.

This is a client correction. No backend deployment, database migration or new
semantic processing consent is required. Existing credentials, configuration,
mail data and unresolved send journals must be preserved. Stop old CLI processes
and their daemon before replacing binaries; verify the new release's checksums
and install its matching Agent Skill. Do not resend an unresolved operation or
re-register an address merely to upgrade the client.

Validation is scoped to the changed lease contract, native acquisition/release
journey and release-platform version/artifact checks, not another full product
regression.
