# amail v0.3.3

Release notes: 2026-10-28 (Asia/Singapore). Formal publication, focused
acceptance and local installation are recorded separately in the
[validation ledger](../validation.md); these notes do not establish publication.

## Local user-profile authorization

Fix normal Approve and Deny clicks receiving `Invalid authorization request.`
on the CLI's local operation-approval page. `Referrer-Policy: no-referrer`
made browsers submit native forms with `Origin: null`, which conflicted with
the required exact loopback origin. The page now uses `same-origin`: native
same-origin form submissions retain their origin, while cross-origin referrers
remain suppressed.

The exact Host, path, origin and one-use action checks are preserved. Null and
cross-origin requests remain rejected. This does not enable YOLO, approve future
operations, change Identity sign-in, or authorize spending or semantic processing.

This is a client correction, with no backend deployment or database migration.
Stop old CLI processes and their daemon before upgrading to the matching release
binary and Agent Skill; preserve credentials, configuration, profiles, mail data
and unresolved send journals. Validation focuses on the approval contract and
real-browser native-form Approve/Deny journeys, not another full mail regression.
