# amail v0.4.0

Release notes: 2026-11-05 (Asia/Singapore). Publication and deployment receipts are
recorded in the [validation ledger](../validation.md).

## Sign in from a remote terminal

`amail login --device-code --no-browser` (also `amail auth login`) uses Identity's
RFC 8628 device flow. Open the verification page on your own device, compare the
application and human code, then explicitly approve. No loopback callback or
local approval page is required. Default browser/PKCE login remains unchanged.

The initiating daemon retains the private device code only in memory, observes
the server interval and persistent slow-down, and stops on denial, expiry or
terminal cancellation. RS256 ID-token validation, encrypted token storage,
serialized rotating refresh and logout/revocation share the existing session.

## Confirm subscriptions on another device

`amail billing subscribe plus --device-code --no-browser` and
`amail billing manage --device-code --no-browser` return an expiring short code
and verification page. The Mail API resolves the code to the existing hosted
Subscribe review session. Opening the page or entering a code does not approve a
plan, payment or budget. Only the authoritative human-approved Billing receipt
changes entitlements; completed authorization is not payment settlement.

Keep the printed creation idempotency key after an uncertain response. Resume the
same session with `amail billing session UUID`; a polling timeout never creates a
replacement financial action. Existing direct hosted links and older clients
remain compatible. Billing navigation/status no longer asks for an unrelated
local operation-approval page; financial confirmation remains in Subscribe.

## Upgrade and operations

This feature requires reviewed Identity client enablement and additive Mail
migration 0020 plus the paired backend. The tagged workflow checks the deployed
backend receipt before publication, builds all five native targets, runs only the
focused device contracts, and validates its exact new Windows executable against
real staging Identity in a browser. Earlier synthetic native/Worker journeys are
retained as integration evidence rather than repeated full mail regressions.

Stop old CLI processes and their daemon before replacing the matching binary and
Agent Skill. Preserve credentials, configuration, profiles, mail state and
unresolved send journals. The upgrade does not require re-registering addresses,
re-sending unknown mail, enabling YOLO or granting semantic-processing consent.
