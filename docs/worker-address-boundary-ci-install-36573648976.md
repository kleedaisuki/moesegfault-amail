# Hosted workerd boundary-test install correction

In [hosted CI run 36573648976](https://github.com/kleedaisuki/moesegfault-amail/actions/runs/36573648976), the new Rust/Wasm Worker boundary test did **not** execute. Its dependency installation failed first with `ERR_PNPM_IGNORED_BUILDS` because pnpm 12.6.0 correctly refused the `workerd@1.20260926.1` package's install script without an explicit project approval. This is an installation gate, not a passing or failing address-add assertion; it gives no evidence about the historical staging HTTP 500.

The boundary-test package declares `allowBuilds: { workerd: true }` in its own `pnpm-workspace.yaml`. No blanket script permission is granted. Cloudflare's `workerd` package is the native runtime that Miniflare invokes, so refusing its install script prevents these tests from starting. This package-level approval does not affect the Astro site or other project dependencies. The existing frozen lockfile remains the source of dependency versions.

The [second hosted run 36574701111](https://github.com/kleedaisuki/moesegfault-amail/actions/runs/36574701111) also stopped **before tests**, this time at `ERR_PNPM_FROZEN_LOCKFILE_WITH_OUTDATED_LOCKFILE`: adding `packageManager` to `package.json` introduced a package-manager lockfile expectation without updating the frozen lock. The package-level pin was therefore removed. The Worker CI job now selects pnpm 12.6.0 with the repository's existing `pnpm/action-setup@v4` pattern (`run_install: false`) before running the frozen install. The install was moved before the expensive Rust/Wasm bundle, while `pnpm test` still runs only after the bundle exists. This keeps the tested manager version explicit without changing the dependency graph or weakening lockfile enforcement.

Verification remains **pending** until a GitHub-hosted rerun performs `pnpm install --frozen-lockfile` and then reaches the actual workerd tests. Per project policy, no local heavy dependency install or Worker build was run for this correction. [pnpm's allow-build documentation](https://pnpm.io/cli/add#--allow-build) and [pnpm 12.7 release notes](https://pnpm.io/blog/releases/12.7) describe the explicit `allowBuilds` mechanism and its security purpose.

The [third hosted run 36575907419](https://github.com/kleedaisuki/moesegfault-amail/actions/runs/36575907419) passed installation and the Rust bundle, but `pnpm test` failed while importing the test module, **before any test assertion**. Cloudflare removed Miniflare's `createFetchMock` export and `fetchMock` option in v5; the previously cited Miniflare fetch-mock documentation was stale for the pinned `5.20260926.0-alpha`. The fixture now uses Miniflare's documented `outboundService` callback instead. It recognizes only one-use synthetic OIDC and Routing URL/method pairs, returns in-memory responses, records unmatched requests as test failures, and never calls Node's global `fetch`. A separate early CI step imports and checks the installed `Miniflare` constructor before the costly Rust build; actual Worker boundary assertions still run after bundling. This change does not prove any address behavior until another hosted test run succeeds. [Cloudflare's v5 removal note](https://newreleases.io/project/github/cloudflare/workers-sdk/release/miniflare%405.20260730.0-alpha) and [current Miniflare `outboundService` API](https://github.com/cloudflare/workers-sdk/blob/main/packages/miniflare/README.md) support the replacement.
