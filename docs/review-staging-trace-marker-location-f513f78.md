## Necessary corrections

1. **P1 — Truncated retained events can be positively classified.** `infra/tests/staging_trace_marker_location.py:93-125` scans the visible leaves but never checks `$workers.truncated`. Cloudflare's [event schema](https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/) exposes that flag. A row with a retained path marker and `truncated: true` can return `component=path_only` even though the missing part may contain the query marker or another carrier. This contradicts the plan's explicit truncated-row fail-closed gate. Reject any true or malformed truncation flag (and test it) before returning bins.

2. **P2 — Required event shape is not validated.** `classify()` checks ID, service, and integer timestamp, but accepts a record lacking the schema-required `dataset` and `source`, or one whose `source` has an unsupported type, so long as a marker appears elsewhere. That returns `CLASSIFIED` for a malformed event despite the plan's missing/malformed-row rejection. Validate the required event envelope and source type before classification; update fixtures to represent valid events and include malformed cases. An absent optional `$metadata.type` may reasonably map to `other_or_mixed`, but required fields should not.

3. **P2 — Output bins disagree with the documented contract.** `docs/staging-trace-canary.md` specifies `cf_worker_event | cf_worker_log | other_or_mixed` and count `0 | 1 | 2_plus`; the implementation prints hyphenated provider types, `other_or_multiple` for mixed types, and labels zero hits `UNVERIFIED (marker_not_located)`. Zero remaining unverified is defensible, but the plan/consumer contract must be reconciled explicitly before hosted use. Prefer a single fixed enum vocabulary in the code, tests, and document; do not imply zero reverses the original positive result.
